## 1. Цели

1. Страницы прогнозов цен для **до ~125 активов** (§3) на **10 языках**, которые находят через Google и AI-системы (ChatGPT, Perplexity, Google AI Overviews).
2. Для каждого актива: график, прогноз на завтра и на 30 дней по дням, среднемесячные прогнозы на текущий год и 2027–2030, годовой прогноз до 2035, технический анализ, точность моделей.
3. **Две схемы формирования страницы:** если поля в админке пустые, страница собирается из шаблона по умолчанию; если поле заполнено, на сайте выводится его значение (§7).
4. **Все опубликованные прогнозы сохраняются**, чтобы сравнивать модели между собой и с фактической ценой (§6.3, §11).
5. Сайт выдерживает высокую нагрузку на минимальном VPS за счёт полного кэширования страниц в Cloudflare (§5.3).

**Цена немецких акций — расчётная цена XETRA в евро (решение владельца 2026-11-04).**

Котировки XETRA на бесплатных тарифах есть только за последние 100 дней (Alpha Vantage, `TIME_SERIES_DAILY`, `BMW.DEX` и т.п.); полная история — только за деньги. Поэтому цена строится так:

1. **Коэффициент ADR рассчитывается автоматически.** Для каждого дня из последних 100 берётся отношение «цена XETRA (EUR) × EUR/USD ÷ цена ADR (USD)»; коэффициент — медиана этих отношений. Пример 2026-11-03: BMW €57,80 × 1,122 ÷ BMWKY $21,17 ≈ 3,06, то есть одна расписка = 1/3 акции. Коэффициент пересчитывается раз в неделю, по две бумаги в день (14 бумаг), чтобы не выйти за 25 запросов Alpha Vantage в сутки. Резкое изменение коэффициента (сплит, смена параметров расписки) останавливает обновление бумаги и вызывает уведомление администратору.
2. **Вся история** до последних 100 дней — цена ADR × коэффициент ÷ EUR/USD того же дня (курс EUR/USD уже загружается для валютной пары).
3. **Последние 100 дней** — фактические закрытия XETRA из Alpha Vantage, там, где они есть.
4. **На странице** цена показывается в евро с пометкой «≈ цена XETRA, расчёт по ADR» для расчётных значений. В методологии объясняется метод, ADR-тикер и текущий коэффициент.
5. В админке коэффициент можно задать вручную. Ручное значение имеет приоритет над автоматическим.

Погрешность расчёта ожидается в пределах ~1% (ADR закрываются в Нью-Йорке позже, чем XETRA). Прогнозы и технический анализ считаются по ряду в евро.

**Нагрузка на Alpha Vantage:** 3 запроса в день (серебро, WTI, Brent) + 2 на пересчёт коэффициента = 5 из 25. Ежедневные фактические закрытия XETRA для 17 бумаг уложились бы в лимит (21 из 25), но без запаса на повторы, поэтому на старте используется расчёт по ADR, а фактические закрытия подтягиваются при пересчёте коэффициента.

Xiaomi, Lenovo и BYD показываются в долларах по ADR: расчётная цена XETRA относится только к 14 немецким бумагам.

**Индексы — через ETF-аналоги (TD):** Nasdaq 100 → QQQ, S&P 500 → SPY, DAX → Global X DAX Germany ETF (DAX). На странице объясняется, что прогноз строится по ETF, повторяющему индекс.

### 3.2 Какие цены показываются
- По каждому дню хранятся и показываются **цена открытия, закрытия и средняя цена** (по умолчанию типичная цена `(High + Low + Close) / 3`; если у источника есть только цена закрытия, средняя = закрытие, а поля открытия и диапазона помечаются как недоступные).
- Валюта USD; единица зависит от актива: за унцию, баррель, MMBtu, галлон, монету, акцию.

### 3.3 Независимость от поставщика
- Каждый поставщик реализован как адаптер с единым интерфейсом (как в малом сайте). Источник актива выбирается в админке (поставщик + символ + запасной поставщик).
- Общий **ограничитель частоты** на каждого поставщика (Twelve Data 8/мин и 800/день, Alpha Vantage 25/день). Ежедневная загрузка ~110 активов укладывается в лимиты с запасом.
- Переход на платные API на этапе 3 — замена ключа и символов в админке, без изменения кода.

### 3.4 Живая цена (тикер)
Бесплатных потоков реального времени для всех классов нет, поэтому:

| Класс | Живая цена | Как |
|---|---|---|
| Криптовалюты | да, в реальном времени | публичный WebSocket Binance прямо в браузере (без ключа, без нагрузки на сервер) |
| Акции и ETF США | да, с задержкой до нескольких минут | Finnhub (бесплатно, 60 запросов/мин): сервер опрашивает котировки во время торгов США, кэш в Redis, отдача через лёгкий эндпоинт с кэшем Cloudflare 60 с |
| Металлы, энергоносители, сельхозтовары | нет | показывается последняя цена закрытия с датой |

Ключей API в браузере нет.

## 4. Прогнозы и технический анализ

Переносятся из малого сайта без изменения логики, с настройками по классу активов:
- **Модели:** ARIMA, тренд + возврат к среднему, Монте-Карло (10 000 траекторий), консенсус.
- **Ограничение долгосрочного роста:** ±25% в год (по умолчанию), действует на всю траекторию прогноза, а не только на наклон тренда. Настраивается для класса и отдельного актива.
- **Проверки:**
  - проверка правдоподобия;
  - walk-forward-бэктест;
  - живая точность по сохранённым прогнозам (§11).
- **Горизонты:** 30 календарных дней по дням, по месяцам до декабря 2030, по годам 2031–2035.
- **Технический анализ:**
  - 12 осцилляторов, SMA/EMA 5–200, 5 наборов pivot-точек;
  - таймфреймы день/неделя/месяц и итоговые сводки;
  - правила сигналов как в малом сайте.
- **Активы с данными только по закрытию** (нефть, газ, дизель): индикаторы, которым нужны максимум и минимум дня (STOCH, ADX, Williams %R, CCI, ATR и др.), не показываются. В сводке это помечается.
- **Версия модели** (`model_version`) сохраняется с каждым прогнозом: при изменении методики старые прогнозы остаются сравнимыми.

## 5. Архитектура и стек

### 5.1 Стек
| Слой | Решение |
|---|---|
| Бэкенд, админка, рендеринг | **Django 5** (Python 3.12), шаблоны Django; админка на базе Django Admin с темой **django-unfold** |
| База данных | **PostgreSQL 16 + TimescaleDB** (гипертаблицы и сжатие для цен и прогнозов) |
| Очереди и расписание | **Celery + Celery Beat**, брокер и кэш **Redis** |
| Расчёты | пакет `pipeline` из малого сайта (pandas, numpy, statsmodels), подключённый как Django-приложение |
| Фронтенд | дизайн-система малого сайта: CSS-токены и компоненты, перенесённые в шаблоны Django; Lightweight Charts для графика; без SPA-фреймворка |
| Переводы | ИИ-перевод через Claude API (§8.3); строки интерфейса — gettext (`.po`) с правкой из админки (django-rosetta) |
| История изменений | django-simple-history (версии шаблонов и ручных значений, откат) |
| Безопасность админки | вход только по 2FA (django-otp), отдельный путь админки, ограничение по IP опционально |

### 5.2 Инфраструктура (минимальный бюджет)
- **1 VPS** (например Hetzner CX32: 4 vCPU, 8 ГБ RAM, ~€7–8/мес), Docker Compose:
  - Caddy (HTTPS)
  - Gunicorn/Django
  - PostgreSQL + TimescaleDB
  - Redis
  - Celery worker и Celery Beat
- **Cloudflare (бесплатный тариф)** перед сервером: DNS, CDN, кэш страниц, защита от DDoS, Web Analytics.
- **Резервные копии:** ежедневный дамп базы в Cloudflare R2 (бесплатно до 10 ГБ), хранение 30 дней; проверка восстановления раз в месяц.
- **Мониторинг:** Healthchecks.io (ежедневные задачи), Uptime Kuma или UptimeRobot (доступность), письмо/Telegram при сбоях.
- **Развёртывание:** GitHub Actions → тесты → сборка образа → деплой на VPS по SSH.
- **Итого:** ~€10/мес плюс домен.

### 5.3 Высокая нагрузка
- Все публичные страницы одинаковы для всех посетителей, поэтому Cloudflare кэширует **HTML целиком** («Cache Everything» для анонимных запросов; `/admin` и API тикера в обход кэша).
- После ежедневного расчёта и после сохранения в админке кэш **сбрасывается точечно** (страницы актива на всех языках, хабы, sitemap) через Cloudflare API.
- До сервера доходит лишь малая доля запросов; сервер рассчитан на ~50 запросов/с при промахах кэша (проверка нагрузочным тестом k6).
- Тяжёлые данные графика отдаются отдельным JSON-файлом с кэшем (как на малом сайте).

## 6. Модель данных (основные таблицы)

### 6.1 Справочники
- `asset_class`: crypto, stock, etf_index, metal, energy, agri. Настройки класса: календарь, ограничение роста, окна истории, единица измерения.
- `asset`:
  - код, тикер, класс, источник/символ/запасной источник;
  - единица, календарь, цвет графика, порядок;
  - флаги `enabled` и `ohlc_basis` (полные OHLC / только закрытие / оценка);
  - ограничение роста (переопределяет класс).
- `asset_translation`: актив × язык → название, **slug** (свой для каждого языка), ключевые слова топ-3.
- `language`: код, включён/выключен, страна для подбора ключевых слов, формат чисел и дат.
- `reviewer`: имя, должность, биография по языкам, фото, профиль. По умолчанию Margerie Holtz.

### 6.2 Рыночные данные
- `price_bar` *(гипертаблица)*: актив, дата, open, high, low, close, avg, volume, источник, признак оценки.
- `live_quote` (в Redis): актив → цена, время.

### 6.3 Прогнозы (сохраняются навсегда)
- `forecast_run`:
  - актив, дата расчёта, время;
  - `model_version`;
  - последняя цена закрытия;
  - параметры и статус каждого метода (JSON).
- `forecast_point` *(гипертаблица, сжатие)*:
  - запуск, метод (`arima` / `reversion` / `montecarlo` / `consensus`);
  - тип горизонта (`daily` / `monthly` / `yearly`), целевая дата или период;
  - значение, P10, P90.

  Хранится всё, что публикуется: ~30 дневных + ~50 месячных + 5 годовых точек на метод. Это ≈ 340 строк на запуск, ≈ 14 млн строк в год для 110 активов, что посильно для одного VPS при сжатии Timescale.
- `forecast_accuracy`: актив, метод, горизонт (1/7/30 дней, месяц), окно (30/90/365 дней), MAPE, MAE, точность направления, попадание в диапазон P10–P90, число наблюдений, дата расчёта.
- `ta_snapshot`: актив, дата, таймфрейм, индикаторы (JSON), сводка.

### 6.4 Контент
- `field_definition`: реестр полей страницы (§7.2): ключ, тип (строка / текст / список / изображение / флаг), раздел, обязательность, подсказка, допустимые подстановки.
- `template`: класс активов × язык × поле → текст шаблона (с вариантами для разнообразия), версия.
- `override`: актив × язык × поле → значение, автор изменения, время.
- `custom_block`: актив × язык → позиция (после раздела X), заголовок, текст, порядок.
- `analyst_target`: как в малом сайте (`analysts.json` → таблица).
- `page`: статические страницы, гайды, сравнения, статьи блога и новости — с переводами, своими slug, SEO-полями и рецензентом.
- `keyword`: актив/страница × язык × страна → ключ, объём, KD, флаг «топ-3», дата сбора.

## 7. Шаблон по умолчанию и ручные значения (ключевое требование)

### 7.1 Правило вывода
Для каждого поля каждой страницы на каждом языке:

1. **Ручное значение** (`override`) для этого актива и языка, если оно заполнено.
2. Иначе **шаблон класса активов** для этого языка.
3. Если шаблона на этом языке ещё нет, язык не публикуется (на этапе 2 язык включается только после перевода всех шаблонов).

Ручное значение на английском **не** подставляется в немецкую версию. Каждый язык заполняется отдельно.

### 7.2 Поля, доступные для правки

- **Тексты:** вступление, сводка, тексты разделов (30 дней, по годам, долгосрочно, технический анализ, точность).
- **FAQ:** добавить, изменить или скрыть вопросы.
- **Факторы цены, аргументы «за» и «против», риски.**
- **Главное изображение.**
- **Показать или скрыть любой раздел.**
- **Собственные блоки** с выбором места на странице.
- **Прогнозы аналитиков.**
- **Автор/рецензент:** по умолчанию Margerie Holtz.

### 7.3 Подстановки
В шаблонах и ручных значениях можно использовать переменные. Тогда написанный вручную текст тоже обновляется каждый день:
`{name}`, `{code}`, `{price}`, `{date}`, `{change_1d}`, `{forecast_tomorrow}`, `{forecast_30d}`, `{forecast_end_year}`, `{forecast_2027}` … `{forecast_2030}`, `{forecast_2035}`, `{p10_2030}`, `{p90_2030}`, `{ta_daily}`, `{ta_weekly}`, `{rsi}`, `{mape_30d}`, `{year}`, `{unit}`.

Числа и даты форматируются по правилам языка: `1.234,56 $` для de, `$1,234.56` для en.

### 7.3а Тексты об активе: ИИ-черновики (решение владельца 2026-11-05)
Тексты с числами строятся по шаблонам (§7.1, §7.3). Факторы цены, аргументы «за» и «против» и риски из формул не получить, а одинаковый шаблон на все активы класса даёт почти одинаковые страницы. Поэтому:

1. Задача в админке создаёт черновик этих полей **один раз на актив и язык** через Claude API, по запуску администратора. Ежедневной генерации нет.
2. Черновик получает статус **«Черновик»** и на сайте не показывается. До подтверждения на странице остаётся шаблон класса.
3. Администратор проверяет факты, правит текст и нажимает **«Подтвердить»** (для одного актива или для выбранных). После этого текст становится обычным ручным значением (§7.1) и попадает в историю версий.
4. Обновление — только по запуску администратора, по одному активу или по выбранным. Новый черновик не заменяет опубликованный текст до подтверждения.
5. Модели не передаются прогнозы и не запрашиваются числа, цены и даты событий: такие утверждения быстро устаревают и могут оказаться неверными. Числа на странице берутся только из базы (§7.3).
6. Нужен ключ Claude API (`ANTHROPIC_API_KEY`) в секретах сервера. Запросы идут с сервера; если API недоступен с IP сервера, черновики создаются другим способом и импортируются через CSV (§7.4).

### 7.4 Админка: как выглядит работа с полями
- На странице актива поля сгруппированы по языкам (вкладки) и разделам страницы.
- У каждого поля видно состояние:
  - **«Шаблон»** — показывается текст по умолчанию с подставленными сегодняшними значениями;
  - **«Своё значение»** — с кнопкой **«Сбросить к шаблону»**.
- **Проверки при сохранении:**
  - неизвестная подстановка → ошибка;
  - топ-3 ключевых слова пропали из title, H1 или H2 → предупреждение;
  - превышена длина title или description → предупреждение.
- Отдельный раздел **«Шаблоны»**: правка шаблона класса активов на каждом языке, включая исправление ИИ-перевода. Изменение шаблона сразу затрагивает все активы класса, где поле не переопределено.
- Есть **история версий** и откат для шаблонов и ручных значений.
- **Экспорт и импорт CSV** для ручных значений и шаблонов. Колонки: `asset`, `language`, `field`, `value` / `class`, `language`, `field`, `template`. Импорт проверяется так же, как ручное сохранение, с отчётом об ошибках.
- **Управление активами:** добавить или отключить актив, сменить источник и символ, запустить загрузку истории и пересчёт.
- **Роль одна: администратор** (по требованию); вход с 2FA.
- **Предпросмотр не нужен:** изменения публикуются сразу после сохранения со сбросом кэша страницы.

## 8. Многоязычность

### 8.1 URL
- Английский в корне (`/bitcoin-price-prediction/`), остальные языки в папках: `/de/…`, `/es/…` и т.д.
- **Slug переводится** по результатам подбора ключевых слов, например `/de/bitcoin-prognose/`. Slug редактируется в админке; при его смене автоматически создаётся 301-редирект.
- `hreflang` для всех включённых языков плюс `x-default` на английскую версию; отдельная карта сайта для каждого языка.

### 8.2 Локализация
- Формат чисел, дат и месяцев по языку; валюта и единицы остаются в USD и тех же единицах.
- Шрифты: для ja, zh, vi нужны начертания с соответствующими символами (Noto Sans JP/SC, полный набор кириллицы и вьетнамских знаков), подключаются только на этих языках.

### 8.3 ИИ-перевод
- При включении языка задача переводит **шаблоны, строки интерфейса, статические страницы и гайды** через Claude API с глоссарием терминов (названия активов, «консенсус», «P10–P90» и т.д.) и с сохранением подстановок.
- Переведённое попадает в админку для проверки и правки (§7.4). Язык публикуется после ручного подтверждения.
- Ключ Claude API хранится в секретах сервера; стоимость перевода одного языка оценивается в несколько долларов.

### 8.4 Юридические документы по языкам
Политики и дисклеймеры переводятся вместе с языком. Для немецкой версии обязателен **Impressum** (§12, §16).

## 10. SEO и AI-поиск

- **Ключевые слова:**
  - для каждого актива и языка собираются через Ahrefs API по шаблонам «[name] prediction / forecast», «[code] prediction / forecast» и их переводам;
  - на запуске — en-US и de-DE, остальное на этапе 2;

- **Query fan-out** для главного ключа каждого актива: документ в репозитории и структура разделов.

- **AI-краулеры:**
  - GPTBot, ClaudeBot, PerplexityBot, Google-Extended разрешены, поскольку трафик ожидается и из AI-систем;
  - файл `llms.txt`;
  - все числа присутствуют в HTML (таблицы, а не только график).
- **Картинки для превью ссылок** с актуальными цифрами для каждого актива и языка.
- **Перенос малого сайта:** URL 8 страниц сохраняются, `*.pages.dev` перенаправляется 301 на новый домен.

## 11. Сравнение моделей и фактической цены

- Ежедневная задача сопоставляет все сохранённые прогнозы (`forecast_point`), чей срок наступил, с фактической ценой (`price_bar`) и пересчитывает `forecast_accuracy`.
- **Метрики:** MAPE, MAE, точность направления (угадан ли рост/падение), доля фактических цен внутри диапазона P10–P90, среднее смещение. Срезы: метод × горизонт × окно × актив × класс.
- **На сайте:**
  - таблица точности на странице актива;
  - отдельная страница-рейтинг;
  - график «прогноз vs факт» для прошлых запусков.
- **В админке:** отчёт с фильтрами и экспорт CSV.
- Пока живых данных меньше 30 наблюдений, показывается walk-forward-бэктест (как на малом сайте). Затем — живая точность.
- **Импорт истории малого сайта:** архивы `data/<asset>/history/forecast-*.json` и цены загружаются в новые таблицы, так что история прогнозов 8 активов не теряется.

## 13. Ежедневный конвейер

- **Celery Beat запускает задачи по классам** с учётом закрытия торгов:
  - криптовалюты — 00:15 UTC;
  - акции и ETF США — после закрытия торгов;
  - энергоносители — после публикации данных EIA (задержка 1–2 дня);
  - металлы — после закрытия FX-дня.
- **Порядок для каждого актива:**
  1. загрузка цен;
  2. проверка (аномальные скачки, пропуски);
  3. прогнозы и технический анализ;
  4. сохранение;
  5. расчёт точности;
  6. сброс кэша Cloudflare;
  7. обновление картинок превью и карты сайта.
- **Ошибка в одном активе не останавливает остальные.** Актив сохраняет вчерашние данные, на странице появляется пометка о задержке, администратору приходит уведомление.
- **Повторы** с экспоненциальной задержкой; соблюдаются лимиты поставщиков (§3.3).
- В админке есть журнал запусков: успех или ошибка по каждому активу и кнопка «перезапустить».
